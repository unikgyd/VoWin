# Rust Linux 主线恢复与完整目标

当前说明：本次更新已按用户最新要求改以 **VoCat-sip** 补齐 Linux，见
[能力并集清单](../VoCat-sip/docs/FEATURE_UNION.md)。以下保留此前 Rust 阶段的决定、
来源边界与成果，不作为本次 Go 工作的主线指令。

2026-10-26，用户决定退出受限 VoCat 主线，继续实现与 VoWin 能力对齐的 Linux 端。
沿用此前的纯 Rust 要求，当前开发基础为工作区 `SimAdmin-sip`；不另建空壳项目，不删除
此前已有的 Rust 协议、设备租约、短信和 SIP 成果。Windows 继续使用 VoWin／VoSharp。

## 项目名称与源码边界

工作区有两个不同项目，不能混称：

- `SimAdmin-sip`：已有的 Rust＋React fork，来源为 SimAdmin 公开主线，工作区 remote
  为 `unikgyd/SimAdmin-sip`；已有新增 Rust 协议核心，不包含官方私有增强版源码。
- `references/mdd-sim-gateway`：MDD Sim Gateway，本地控制面和 SWu Engine 主要为
  Python，并包含 Asterisk／容器组件，不是上述 Rust fork。

用户随后明确确认：主线就是现有 `SimAdmin-sip`，VoCat 与 MDD 作参考，快速补齐。
因此不另建项目，也不将 MDD 的 Python／Asterisk Engine 换名当作 Rust 实现；不安装
MDD 运行栈或用它替换现有服务。

VoCat 的代码、二进制和运行时不进入 Rust 构建。其既有测试结果仍作为历史记录，不能
充当 Rust 新实现的验证结果。实现依据采用公开协议、自有 VoSharp 行为契约及逐文件
许可适合的参考；不将受限 Go 源码机械翻译成 Rust。MDD、pagecat 等同谱系实现不算
多份独立正确性证据，参考的来源和适用边界仍应保留。

## 完整交付要求

| 范围 | 要达到的实际行为 | 不能代替验收的证据 |
| --- | --- | --- |
| 多模组 | 每台模组有独立模式、会话、SIM 绑定、重连和清理；一台停止不影响另一台 | 配置字段、全局第一台回退、模拟双线路 |
| Host IMS | 自动绑定所选 QMI／承载，真实 SIM AKA、地址／P-CSCF／ESP、注册续期，再接通话和短信 | 发现 QMI 端点、分组件回环或仅 REGISTER |
| VoWiFi | 按卡多归属候选、手工 ePDG、成功记忆、外内层双栈、完整 IKE／EAP／AUTH 和实际 IMS 生命周期 | 解析到 ePDG、IKE 初始握手或存在未接线接口 |
| 电话和 SIP | 内线、来显、群振首接、运营商入呼／外呼、双腿取消／挂断、双向媒体；Asterisk 可选 | AT 拨号或 SIP 200／RTP 包计数 |
| 模组语音桥接 | 选中硬件的 USB 音频、媒体所有权及错误／挂断后回收，不使用默认桌面声卡兜底 | 声卡存在或只收到单向 PCM |
| 短信和消息 | 原线路收发、分段、报告、SIP MESSAGE、入库、通知和持久化防重；未知收费结果不自动重发 | SIP 202、RP-ACK 或单条模块短信 |
| 工程和管理 | 按模式真实状态、必要提示、配置恢复、快速退出、详细脱敏日志、通知交互和只读 Token API | 诊断页、灰色占位开关或仅库测试 |
| 发布和验收 | NAS 原生构建／部署、多模组热插拔／换卡、跨网段软电话、升级与回滚；Windows 包保持轻量 | WSL 验证、单模组注册、其他项目的旧绿色记录 |

新主线仍未达到以上完整目标。各阶段需保存原失败、当前源清单与实际构建／运行证据，
不通过减少目标、移除失败断言或改写跳过项来宣告完成。
