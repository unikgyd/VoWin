# SIP 收件持久转发

2026-10-24：Windows 的实际桌面收件入口新增 MT 持久队列。发送手机短信的收费准入仍见
[持久防重](SIP_SMS_DURABILITY.md)，原卡回复规则见 [来源绑定](SIP_SMS_SIM_BINDING.md)。
三者不是同一个状态机：MT 向软电话投递不需要重新发送运营商短信，也不消耗 SIM 外发短信。

## 收件与投递

真实 `Kernel.SmsReceived` 回调在第一次异步等待前捕获当时配置的本地分机和固定中继，
包含离线分机，同时捕获原 runtime 的 canonical 回复号码。桌面在同一 SQLite 写事务保存
Inbox、来源收据及逐收件人转发意图，包括独立于原始发件人显示的回复快照；
提交成功后才通知 UI／推送及唤醒 SIP worker。配置了持久存储时，原直接转发回调退出，
不会一条短信同时走内存直发和持久队列。缺少实际持久存储时拒绝启用桌面收件转发。

当前没有历史扫描补发。手动同步模组存储及旧数据库记录使用空转发计划；新建账号、
修改配置或启动 worker 不能给它们追加新收件人。网络重复事件也不能扩展第一次的计划。
来源不明仍可通知，但回复地址只读；队列不从“现在插着的卡”补卡身份。

首次升级创建来源收据表时，会在同一 SQLite 写事务中为已有收件箱登记空计划收据，
只读取当时已保存的来源字段，不读取正文、不生成转发队列，也不推断当前 SIM。
期限从迁移时起算二十四小时，避免旧短信时间使保护立即过期；超过来源容量则持久化
保护窗口。已有收据表的重启不重扫历史、不延长期限。升级前已删除的来源无法凭空恢复；
旧记录缺少稳定 source ID 时仍只有原行 ID 的保护，不能证明换行 ID 的网络重投。

队列固定原线路、卡摘要、原发件人及正文指纹，正文仍取实际 Inbox 行。读取候选后，
claim 事务再次检查行存在、方向及当前内容；已删除或修改的待投消息取消，不发旧拷贝。
原发件人的空白不会被 Inbox 的号码规范化悄悄变成可付费回复的号码。

回复目标以同一 Inbox／收据首次成功持久准入为界冻结；并发重复事件由首次成功提交者
决定，不承诺网络物理最早到达。新收件的 `SipReplyNumberSnapshot` 与 queue 的
`ReplyNumberSnapshot` 同事务保存，non-null payload-v2 指纹包含它。`null` 保持旧 v1
指纹兼容，只可从原始严格国际号码保留回复；空串是新显式只读，不能按后来的国家码补值。
实际 Inbox／队列快照必须完全一致，claim 和每次 wire guard 都核对，不能篡改队列来重定向。
普通历史保存不覆盖或补填首值。迁移只增加可空列，不改旧正文、收据、期限、Unknown 或收件人。
此保证范围是 SIP MT 原卡回复，不改变桌面手动输入号码的普通 MO 路由。

2026-10-24 后续已补齐 claim 后的实际来源核验：原 Inbox 引用、intent ID、Unknown、
attempt token、接收人、期限及载荷在同一只读快照中比对；实际来源 ID／卡／线路重新计算
原 intent ID，不能改指同内容的另一 Inbox 行。该读取不建表、不写状态或续期。
每次 MT UDP 初发、每片、401／407 后认证和超时重传都先检查运行权限／Contact，
等待实际 Store 核验后同步再查运行权限／Contact，随后才发包。数据库等待期间若已收到
合法最终响应，消费该响应而不继续重传；错误或取消保留 Unknown，不自动重发。
检查与网络不是原子提交，已发载荷不能撤回，不能承诺阻止最后检查后的瞬时并发变化。
独立库宿主须实现 `IsClaimSourceCurrentAsync`，并由真实 claim 填写原 `InboxId`；
不能用固定 true 的兼容实现绕过来源核验。独立验证见[发送前核验阶段](../../publish/windows-sms-wire-guard-20261024/README.md)。

本地分机离线保持 Queued，REGISTER 成功可唤醒投递。固定中继没有 REGISTER 上线事件，
先用独立、短时缓存的无正文 OPTIONS 探测：200 或符合明确 Realm／算法的 401／407 才
表示可达。探测不发送 Authorization、短信正文、发件人手机号或卡绑定；失败继续等待。
可达不是 MESSAGE 接受保证，也不是运营商送达证明。

这里的离线等待依据“没有有效本地注册”或“peer 探测失败”。若 Contact 仍有效但手机
已休眠／丢包，实际尝试后仍可能成为 Unknown；下次 REGISTER 不会自动重发该未知尝试。
本功能不提供 iOS PushKit／后台唤醒，也不把 OPTIONS 当成终端在线或最终阅读证明。

整体并发最多四个收件人，固定 peer 最多占一个；不同本地分机不被慢中继串行阻塞。
Windows 的排队、探测、所有联系人／分片和每片至多一次认证重试共享八秒预算。claim 前后及每片发送前
复核联系人，已注销的旧 Contact 不继续投递。

## 显式 MESSAGE 分段

MT 准入要求非空、无 NUL、严格 Unicode 文本，最多 16,384 个 UTF-16 单元；补充平面
字符占两个单元，不是 16,384 字节或字符。按 Unicode scalar 边界切成每块最多 280 个
UTF-8 原文字节，多块才添加可见 `[i/n] ` 前缀；单块保持原文，包括原有的 `[1/2]` 文本。
前缀不占这 280 字节，但前缀、全部 SIP 头及认证仍受整包 1,300 字节上限约束；长头部
仍可能安全拒绝，分段不保证任意配置都能发送。

固定样例见[双端分段契约](../../contracts/sip-message-parts-v1.json)。切分不规范化文本，
不保证组合字符或 CRLF 整体不拆；这是应用层可见多消息，不是运营商 TPDU／UDH，
也不提供软电话透明重组。所有分段、联系人和探测共享原总期限，不逐片续期。
该规则只描述 MT 转发，不扩大普通分机 MESSAGE 或手机 MO 短信的准入。

## 不确定结果不重试

在任何 MT MESSAGE 载荷或其认证请求发送前，SQLite 用跨实例写事务抢占 intent，
以 `synchronous=FULL` 提交 Unknown 和随机 attempt token，再允许发包。
其他使用同一文件的实例不能再次获得此 intent。离线检测本身不 claim，也不含短信内容。

至少一个联系人必须接受同一逻辑短信的全部分片，才标记 Accepted；不能拼接多个联系人
各自接受的不同片段。超时、拒绝、部分接受、取消、崩溃或完成状态写入失败均保持 Unknown，
不会自动变回 Queued。Accepted 只表示该 SIP 收件人接受，不保证手机展示或用户已读；
对 Asterisk peer 只证明 PBX 接受，无法证明其后的所有分机收到。

完成更新必须匹配原 intent 的 attempt token，且不能把 Accepted 降回 Unknown。
迟到任务不能完成过期后同 ID 的新尝试。普通停止保留 Queued，不把关闭程序误作撤销账号。
已抢占但停机中断的任务仍保持 Unknown；不提供“清空未知后自动重发”的捷径。

## 收件人身份

本地账号和固定 peer 各有持久随机代际，纳入 DPAPI 的完整设置绑定。正常保存、停用和
恢复不旋转；改账号／密码、删除重建、导入及显式“重置接收身份”会生成新代际。
同用户名、同密码重建也不会继承旧短信。UI／启动恢复先保存实际代际，再启用监听。
身份摘要还绑定凭据上下文；peer 包括端点、目标、双向凭据及 Realm／算法固定。

同值密码设置无法仅靠属性变更检测，所以设置提供明确的重置操作，不改密码本身。
编辑须先关闭 SIP；保存后再开启才使用新身份。分机的原“允许发送短信”是付费外发权限，
不是接收权限，不会因它默认关闭而阻止 MT 接收。

独立库宿主若不持久提供代际，每个 runtime 得到独立随机代际，不能跨重启继承旧队列。
已配置的 peer 是一个收件人；其后 PBX 的账号／群组变动必须由 PBX 自己保证隐私，VoWin
不能证明那些终端的身份。接收身份重置也不负责擦除软电话已经缓存的短信。

## 有界来源保护

| 表 | 保存内容与用途 |
| --- | --- |
| `SipSmsForwards` | 原 Inbox 引用、原发件人快照、收件人身份摘要、内容指纹、期限、状态及 attempt token；不另存正文或明文 SIP 密码 |
| `SipSmsForwardReceipts` | 独立的原线路／SIM／source ID 摘要和期限，防止删除 Inbox 后重放同一来源给新账号，空计划和不支持的内容也记收据 |
| `SipSmsForwardReceiptGuard` | 来源收据容量满时的持久保护期限，避免未记住的来源在释放容量后被当成新消息 |

intent 最多 2,048 项，终态和 Unknown 也占用容量；每项保留二十四小时。
来源收据最多 32,768 项；满后本地收件仍可保存，但新转发在最后一个未记录来源后的
二十四小时保护窗口内暂停，释放一点容量不会取消该保护。原收据不因重复事件延长期限。
超过 SIP 支持范围的正文／发件人仍保存本地短信，但不生成计划，不伪称容量满；数据库
故障或不合法的收件人元数据则回滚原子事务并记失败类别，不静默改走内存转发。

过期回收前验证来源记录与保护期限；损坏记录不当空库。身份／正文摘要不等于磁盘加密，
数据库仍含私有短信及收件人信息，需保护原有访问权限。日志不输出正文、身份摘要或密码。

这是基于系统 UTC 的有界保护，不是永久 exactly-once。时钟大幅跳变、删除／替换数据库、
恢复旧备份或缺少可信稳定 source ID，都不能据此承诺无限期识别同一原消息。
已经在途的消息也不能通过删除 Inbox 撤回。

Rust MT 也不因此成为持久队列。
Go 已使用前述 MT 专用传输覆盖实际 UDP 自动重传，不把普通 sipgo 缓存重传当成来源核验。

本阶段不替换现用程序或生产 PBX、不操作模组／实卡、不发真实短信或电话；Linux 验证
只在指定服务器，不使用 WSL。真实软电话、运营商短信及生产部署仍需各自独立验收。
