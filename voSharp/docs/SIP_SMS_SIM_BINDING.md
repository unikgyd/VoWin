# SIP 短信原卡回复与来源快照

2026-10-24：Windows 将原先只绑定模组的回复地址改为同时绑定原线路和已核实的 SIM。
这是沿用 Linux 参考实现的原卡原则后独立实现的 Windows 业务接线，不是复制受限源码。
不新增运行时、驱动或系统服务；不自动启用收费短信。

## 回复地址

从实际接收会话取得有效卡身份，并已固定严格国际回复号码的短信，生成：

```text
sms2-<12位线路摘要>-<43字符卡摘要base64url>-<首次固定的+国际号码>
```

卡摘要为完整 SHA-256，base64url 编码其 32 字节，不截短为短卡号；不在 URI 中放明文
ICCID。编码大小写敏感、无 padding，解码后须重新编码一致。最长地址 78 字符，避开
隔离 Asterisk 测试中发现的 79 字符分机截断边界，不从可伪造的 To 地址补回被截断部分。
它不是发送权限或保密 Token；已有 SIP 鉴权、用户／peer 与逐线路短信权限仍全部适用。

回复目标在该 Inbox／收据首次成功持久准入时固定。Windows 在每个收件事件第一次数据库
等待前捕获原 runtime 的国家策略；国内号码只在原线路显式 `NormalizeE164`、国家码与
国内号码长度精确匹配时补成国际号码，不走默认线路或拨号规则，不猜测漫游网络。
原始发件人仍用于显示。具体存储与验证见[canonical 阶段记录](../../publish/windows-sms-canonical-20261024/README.md)。

后改国家码、国内号码长度或 normalize 开关不重新解释已准入源。历史记录缺少快照时只
保留本来就严格有效的 `+` 国际号码；纯国内号码别名即使能被旧 codec 解码，也返回 403，
不凭当前设置变成收费回复。显式只读空串不回填，未知 SIM 不补当前卡证明。
这是有意收紧旧别名行为；普通手动输入号码的 MO 路由仍使用当前配置。

回复只允许原线路上的同一张已核实卡。原线路删除、禁用、卡片更换、身份未知、显式选线
冲突时拒绝，不换卡、不用默认线路。旧的线路级地址、此前未发布的长十六进制地址以及
无来源证明、无法确定国家的国内号码、短码、字母发件人使用的只读地址均不能触发收费回复。桌面已配置线路的
普通号码外发也会捕获所选线路的当前卡身份，再进入同一个受保护发送入口；独立宿主
仍须正确配置线路并使用新控制器，旧兼容接口不因此获得同等保证。

别名无独立到期时间，也不提供账号重建隔离。原卡重新核实后，新请求可以继续使用原卡
别名；已进入原卡发送入口、停止／切卡前排队的旧任务不能因此复活。当前不承诺外部进程不会操作模组，
也不能把软件代际校验解释为物理换卡瞬间的原子锁。

## 从入口到实际写入

- Kernel 在等待模组操作租约之前捕获原 slot 对象、SIM、代际及取消令牌；slot 在排队
  等待 Profile 锁之前捕获或核对同一 owner，取得锁后再复核。等待计入 25 秒总预算。
- 受管的 SIM 切换、eUICC 修改、飞行模式和可能改卡的调试写入先使旧短信 owner 失效。
  调试 AT 仅明确的只读白名单保留身份；未知写入会停止旧会话、清除已核实身份，需重新
  刷新验证，不用猜测写入的副作用。
- Host IMS 固定原已注册客户端与卡身份；VoWiFi 固定接收／发送 source 的传输、注册
  信息和短信中心。每个 source 拥有独立的长短信重组及入站事务缓存，旧回调不借用新卡。
- 公开停止立即使 source 失效，再等待生命周期与恢复任务；已排队启动或迟到注册不能
  重新发布被停止的 source。网络等待不持有 VoWiFi 生命周期锁。
- AT 发送不仅在排队前检查，还在收到 `>` 提示符后、写 PDU 和 Ctrl+Z 的实际边界复核
  owner 与取消；身份失效则不写载荷，并走已有 ESC 清理。

收费准入仍使用 [SQLite 持久防重](SIP_SMS_DURABILITY.md)。V3 内容指纹新增原 SIM
绑定；旧 operation ID 完全不变，旧 V1／V2 准入记录不因升级获得新的发送机会。
新的 bound-send 接口不能借用旧 idempotent 接口的保证绕过存储。异常或取消保持
Unknown，不自动重发；这不代表运营商或手机端 exactly-once。

## 收件入库

真实接收事件携带接收会话的卡摘要，不在处理延迟后读取“当前 SIM”补身份。桌面保留
原消息 ID、线路和卡摘要，SQLite 原子判重并提交后才更新列表及通知。不同线路、卡片、
已知／未知来源不会互相吞信；相同作用域的重复事件不重复通知。源元数据由所有内部
查询路径保留，但不通过公共短信模型 JSON 暴露。

旧数据库迁移只增加可空列，不回填猜测。模组存储里的历史短信没有可信接收会话来源，
因此仍为未知卡；即使当前插着同一张卡也不自动赋予收费回复能力。

## 尚未完成

本原卡绑定阶段**没有实现 MT 持久离线队列**；随后 Windows 已接入
[收件持久转发](SIP_SMS_FORWARDING.md)，包含收件／意图原子保存、账号／peer 凭据代际、
Unknown 不自动重发、分片整体接受与 token 防迟到完成。新阶段的完整验收状态以其记录为准，
不将本文旧阶段组件结果当作队列验证。
Rust 参考端的 MT 转发也不是持久队列。Go 已有持久 outbox，但设置整块写入不能当成
跨进程 SQLite CAS，本地同密码删除重建账号的隔离仍需补齐。

参数化 Asterisk 生成器仍需对齐新的双向独立凭据 profile；本阶段别名路由测试不等于
已完成新版配置自动部署、Linux 别名长度统一或真实软电话／实卡验收。

软件、隔离 PBX 与保留的失败证据见
[阶段验证记录](../../publish/sip-sim-binding-20261024/README.md)。本阶段不替换现用程序、
不修改生产 PBX、不注册运营商、不拨号或发真实短信，Linux 测试仅使用指定服务器而非 WSL。
